# Help test Shep

The app and installers are still in private preview. This guide is for invited testers now and community testers when downloads become public.

## Try it on your setup

Automated builds and packaged-window smoke checks ran on Windows, macOS, and Linux. We still need everyday use on real computers and phones, especially Mac and Linux.

Check installation and launch, Tailscale pairing, opening and switching panes, typing and scrolling, reconnecting, notifications, and startup at sign-in. Test with a disposable session first. Include your desktop OS/version, CPU architecture, phone/browser, and Shep version in your report.

## Report a problem

When the repository is public, open a GitHub issue. Tell us what you tried, what you expected, what happened, and how to repeat it. A short recording helps. Remove API keys, pairing QR codes and links, account identifiers, private chats, and personal paths from screenshots and logs.

## Send a fix

Open a pull request with a focused change, the problem it solves, and how you tested it. See [developer setup](docs/DEVELOPMENT.md) for local commands. Keep unrelated changes out of the patch. If you could not test a platform or device, say so.

Testing and fixes both help. With your permission, we’ll thank you in the release notes using your preferred public name or GitHub handle. Code contributions keep their actual authorship.
